NVIDIA <sup>®</sup> DeepStream Software Development Kit (SDK) is an accelerated AI framework to build intelligent video analytics (IVA) pipelines. DeepStream runs on NVIDIA <sup>®</sup> T4, NVIDIA® Hopper, NVIDIA <sup>®</sup> Blackwell, NVIDIA <sup>®</sup> Ampere, NVIDIA <sup>®</sup> ADA, NVIDIA® DGX Spark, and platforms such as NVIDIA <sup>®</sup> Jetson AGX Thor, NVIDIA <sup>®</sup> Jetson Orin and NVIDIA <sup>®</sup> IGX Thor. For dGPU platforms Enterprise GPUs are highly recommended for deployments that are expected to run 24x7. Gaming GPUs are not designed to perform in such type of environments.

## DeepStream 9.2.1 upgrade targets

This checkout's source and packaging version is **9.2.1**; its installation
directory remains `/opt/nvidia/deepstream/deepstream-9.2/`. The configured upgrade
targets below are separate from the older published 9.2.0 packages and container
tags. A configured target is not a completed build or runtime qualification.

| Platform | Environment / container input | CUDA | TensorRT | cuDNN | VPI |
| --- | --- | --- | --- | --- | --- |
| x86 dGPU | Ubuntu 24.04 / Python 3.12; matching AMD64 Triton 26.10 server/client images | 13.4.3 | 11.4.0.106 | 9.27.0.42 | 4.1.3 |
| Generic SBSA / DGX Spark | Ubuntu 24.04 / Python 3.12 container; matching ARM64 Triton 26.10 server/client images | 13.4.3 | 11.4.0.106 | 9.27.0.42 | 4.1.6, genuine SBSA inputs required |
| Jetson AGX Orin / Thor | JetPack 7.2.2+ with matching BSP; explicitly supplied compatible Python 3.12 image(s) | 13.2.2 | 11.4.1.31 | 9.20.0.46 | 4.1.6 |

The x86/SBSA core versions follow the [NVIDIA 26.10 container contents](https://docs.nvidia.com/deeplearning/frameworks/cuda-dl-release-notes/rel-26-10.html).
Jetson eligibility follows the [TensorRT 11.4.1 Jetson migration guide](https://docs.nvidia.com/deeplearning/tensorrt/11.4.1/api/migration/tensorrt-10x-to-11x-jetson.html).
The separate IGX legacy target is unchanged by this upgrade. DLA with TensorRT
11.4.1 is an AGX Orin / JetPack path, not a Thor or generic SBSA capability.

`CUDA_VER` selects the toolkit family directory: **13.4** for x86/SBSA and
**13.2** for Jetson. It does not install or verify the full patch release.
Containers still need a compatible host NVIDIA driver or Jetson BSP. Use a
driver supported by the selected CUDA/container release; the old 595.58.03
baseline in the historical tables below is not the new driver recommendation.

The monorepo Dockerfiles assemble a matching SDK tarball; they do not compile the
SDK sources. Use the source-matched 9.2.1 runtime and the provider requirements in
`deepstream_dockers/README.md`. No new published image tag is implied. Jetson
requires its own reviewed provider rather than stock SBSA Triton 26.10. See
[Docker Containers](/text/DS_docker_containers#deepstream-921-upgrade-recipes).

## Install from the GitHub Mono-repo (Build from Source)

The DeepStream mono-repo at https://github.com/NVIDIA/DeepStream contains the
open-source components (GStreamer plugins, utilities, sample, reference and TAO
applications, and Service Maker) together with `build/build.sh`. It can install
release artifacts, build source components, or assemble a supplied complete SDK
runtime with the available sources. The installation directory is
`/opt/nvidia/deepstream/deepstream-9.2/`.

<Note>
The default artifact pins still select the published **v9.2.0** assets. Do not
combine those older binaries with the TensorRT 11 upgrade merely because the
installation directory is also named `9.2`. For the upgrade, provision a matching
rebuilt runtime and use `--skip-artifacts` when rebuilding sources, or
`--package-from` when assembling an approved complete runtime. Neither option
converts older binaries to the new stack.
</Note>

### Choose an installation method

| Method | Use when |
|---|---|
| Mono-repo build (`build/build.sh`) | You want the sources, or need to modify, rebuild or extend DeepStream components. |
| Release packages (`.deb` / `.tbz2`) | You want a binary installation without building. See the platform sections below. |
| Container | You want a ready-made environment with the compute stack installed. See [Docker Containers](/text/DS_docker_containers). |

### Prerequisites

- The NVIDIA compute stack (driver, CUDA, cuDNN and TensorRT) for your platform.
  Match the [9.2.1 upgrade targets](#deepstream-921-upgrade-targets), not the
  older published-release tables, when building this upgrade.
- `git`, `git-lfs`, `cmake` and `wget`.
- SBSA / DGX Spark: bare-metal installation is not supported. Build inside the DeepStream SBSA container instead. See [FAQ for DeepStream GitHub Mono-repo](/text/DS_Monorepo_FAQ).

For the complete list of system packages per platform, see `build/BUILD.md` in the mono-repo.

### Build and install

```bash
# Install Git LFS (required for LFS-tracked sample media)
sudo apt-get install git-lfs && git lfs install

# Clone the repo with submodules
git clone --recurse-submodules https://github.com/NVIDIA/DeepStream.git && cd DeepStream

# Check out the reviewed upgrade revision; the default remote branch is not
# evidence that its sources and runtime inputs match your selected drop.
: "${DS_SOURCE_REVISION:?Set the reviewed DeepStream 9.2.1 source revision}"
git checkout "$DS_SOURCE_REVISION"
git submodule update --init --recursive

# Upgrade source build: first provision the matching SDK runtime, compute stack,
# Triton client SDK and development dependencies described in build/BUILD.md.
# Do not install the older default release artifacts over that runtime.
bash build/build.sh --skip-artifacts
```

For a full build without stage-skipping options, `build/build.sh` detects the
platform and runs these stages in order:

1. `artifacts`: downloads the prebuilt runtime libraries and sample data from the [DeepStream GitHub release](https://github.com/NVIDIA/DeepStream/releases) and installs them (x86 and Jetson).
2. `deps`: builds and installs the open-source dependencies.
3. Source stages: `gst-utils`, `utils`, `gst-plugins`, `sample_apps`, `yolo`, `tao_apps`, `reference_apps` and `service-maker`.
4. `install.sh`: registers the binaries and installs the `pyservicemaker` Python wheel.

A transcript of each run is written to `build/build.log`.

Commonly used options:

| Option | Description |
|---|---|
| `--only=STAGE[,STAGE]` | Build only the named component stage(s). |
| `--resume` | Skip stages already completed, after an interrupted build. |
| `--skip-deps`, `--skip-artifacts` | Skip the dependency or artifact install when it is already done. |
| `--install-method=<deb or tar>` | Install the release assets from Debian packages (`deb`, the default) or tarballs (`tar`). |
| `--keep-assets` | Keep the downloaded release assets in `artifacts/` after a successful build. |
| `-j N` | Number of parallel build jobs. |
| `--verbose` | Show sub-make errors. |

Source/package defaults are `NVDS_VERSION=9.2.1` and `CUDA_VER=13.4` on x86/SBSA
or `13.2` on Jetson (`13.0` on unchanged IGX). `pyservicemaker` keeps its
independent version **0.0.1**. Run `bash build/build.sh --help` for all options.
For offline assembly without downloading, installing dependencies or compiling:

```bash
bash build/build.sh --package \
  --package-from=/absolute/path/extracted-sdk/opt/nvidia/deepstream/deepstream-9.2 \
  --package-platform=x86
```

Use `--package-platform=jetson` or `sbsa` for a matching ARM runtime. This is
packaging, not a cross-build or proof that supplied binaries match the sources.

### Verify the installation

After installation, follow `samples/modelopt/README.md` to prepare FP16/mixed
models for TensorRT 11. Original ONNX filenames remain canonical; preserved FP32
models use the `fp32_` prefix. Preparation installs its own tool dependencies only
when explicitly run, and target engines are built afterward. Validate accuracy,
latency and memory on the target; conversion alone is not qualification.

Then clear the GStreamer plugin cache and run the reference application:

```bash
rm -rf ~/.cache/gstreamer-1.0/
cd /opt/nvidia/deepstream/deepstream-9.2/samples/configs/deepstream-app
deepstream-app -c source30_1080p_dec_infer-resnet_tiled_display.txt
```

### Notes

- `build/build.sh` does not build `gst-nvdsudp`, `gst-dsexample-cuda` or `gst-nvdstextembedder`. Build these separately by following the README in each component directory.
- Some sample applications are platform-specific and are skipped automatically on platforms where they are not supported.
- On Jetson Orin, use external storage: the downloaded release assets can exhaust internal storage.
- On SBSA / DGX Spark, to modify a single open-source component, run `make` in that component's directory inside the container. See [FAQ for DeepStream GitHub Mono-repo](/text/DS_Monorepo_FAQ).

For the full build reference, including uninstall, Service Maker local compilation and packaging, see `build/BUILD.md` in the mono-repo.

## Jetson Setup

This section explains how to prepare a Jetson device before installing the DeepStream SDK.

<Note>
Steps to install DeepStream SDK locally, assume that `~/.local/bin/` has been added to the `~/.bashrc` or `~/.profile`
</Note>

### Install Jetson SDK components

Download NVIDIA SDK Manager from https://developer.nvidia.com/embedded/jetpack.
For the TensorRT 11 upgrade, provision JetPack **7.2.2+** and its matching BSP on
an eligible **AGX Orin or Thor** device, with the component versions in the
[upgrade target matrix](#deepstream-921-upgrade-targets). Do not infer support for
other Orin modules from an earlier DeepStream release's compatibility table.

- NVIDIA SDK Manager is a graphical application which flashes and installs the JetPack packages.
- The flashing procedure takes approximately 10-30 minutes, depending on the host system.

### Install Dependencies

#### Install prerequisite packages

Enter the following commands to install the prerequisite packages:

```
$ sudo apt install \
libssl3 \
libssl-dev \
libcurl4-openssl-dev \
libgstreamer1.0-0 \
gstreamer1.0-tools \
gstreamer1.0-plugins-good \
gstreamer1.0-plugins-bad \
gstreamer1.0-plugins-ugly \
gstreamer1.0-libav \
libgstreamer-plugins-base1.0-dev \
libgstrtspserver-1.0-0 \
libjansson4 \
libyaml-cpp-dev \
libmosquitto1
```

<Note>
Sometimes with RTSP streams the application gets stuck on reaching EOS. This is because of an issue in rtpjitterbuffer component.
To fix this issue,
On baremetal, run a script "update_rtpmanager.sh" at `/opt/nvidia/deepstream/deepstream/`. The script should be executed once user installs packages mentioned under "Install Dependencies" section of Quickstart Guide.
On docker, users need to run user_additional_install.sh script to use the prebuilt binaries.
</Note>

##### Install OpenTelemetry

Enter the following commands to install OpenTelemetry:

```
$ cd ~
$ mkdir otel_src && cd otel_src && git clone --branch v1.23.0 --recurse-submodules https://github.com/open-telemetry/opentelemetry-cpp
$ cd opentelemetry-cpp
$ mkdir build && cd build
$ sudo apt install cmake
$ cmake .. -DBUILD_SHARED_LIBS=ON -DWITH_OTLP_GRPC=ON -DWITH_OTLP_HTTP=ON -DBUILD_TESTING=OFF
$ cmake --build . --parallel $(nproc)
$ ctest -V (Optional: run tests for verification)
$ sudo cmake --install .
```

<Note>
For more information, refer to the OpenTelemetry C++ installation guide:
https://github.com/open-telemetry/opentelemetry-cpp/blob/v1.23.0/INSTALL.md
</Note>

#### Install librdkafka (to enable Kafka protocol adaptor for message broker)

1. Install confluent-platform:

```
sudo mkdir -p /etc/apt/keyrings

wget -qO - https://packages.confluent.io/deb/8.0/archive.key | gpg \
--dearmor | sudo tee /etc/apt/keyrings/confluent.gpg > /dev/null

CP_DIST=$(lsb_release -cs)
echo "Types: deb
URIs: https://packages.confluent.io/deb/8.0
Suites: stable
Components: main
Architectures: $(dpkg --print-architecture)
Signed-by: /etc/apt/keyrings/confluent.gpg

Types: deb
URIs: https://packages.confluent.io/clients/deb/
Suites: ${CP_DIST}
Components: main
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/confluent.gpg" | sudo tee /etc/apt/sources.list.d/confluent-platform.sources > /dev/null

sudo apt-get update && sudo apt-get install confluent-platform
```

2. Install librdkafka:

```
sudo apt-get install librdkafka-dev
```

#### Install matching NVIDIA BSP packages

Keep the BSP and user-space packages matched to the selected JetPack release.
Do not replace just TensorRT beneath older Triton backends. For Docker delivery,
use the explicit Jetson image providers described in the monorepo Docker guide.

## dGPU on ARM Setup for Ubuntu

This section explains how to prepare an `Ubuntu aarch64` system with NVIDIA dGPU devices before installing the DeepStream SDK.

You must install the following components:

- A host NVIDIA driver compatible with CUDA 13.4.3 and the selected ARM64 image
- Docker
- Nvidia Container Toolkit

### Install a compatible NVIDIA driver

Follow the [NVIDIA driver installation guide](https://docs.nvidia.com/datacenter/tesla/driver-installation-guide/index.html)
for the ARM64 host and selected CUDA/container release. Verify the loaded driver
with `nvidia-smi`. Installing a user-space container does not update that driver.

### Run dGPU on ARM Docker (SBSA)

<Note>
A compatible NVIDIA driver must be installed on the host for SBSA. The driver is not included in the Docker image; the NVIDIA Container Toolkit makes the host driver available to the container.
</Note>

1. Set `DS_SBSA_IMAGE` to the reviewed DeepStream image built with the monorepo
   SBSA recipe and matching 26.10 inputs, then pull it if stored in a registry.

```bash
: "${DS_SBSA_IMAGE:?Set a reviewed DeepStream 9.2.1 SBSA Triton image reference}"
docker pull "$DS_SBSA_IMAGE"
```

2. Start the docker

```bash
sudo docker run -it --rm --runtime=nvidia --network=host -e NVIDIA_DRIVER_CAPABILITIES=compute,utility,video,graphics --gpus all -e DISPLAY=:0 -v /tmp/.X11-unix:/tmp/.X11-unix -v /etc/X11:/etc/X11 "$DS_SBSA_IMAGE"
```

<Note>
`--privileged` is omitted above; add it only if the container needs access to all host devices or low-level driver operations. It grants near-root host access, so on shared or production systems prefer `--device` / `--cap-add` instead.
</Note>

## DGX Spark Setup for Ubuntu

This section explains how to prepare a [NVIDIA DGX Spark](https://www.nvidia.com/en-us/products/workstations/dgx-spark/)
system before installing DeepStream SDK. DGX Spark is an aarch64-based desktop AI system
running Ubuntu with an integrated NVIDIA Grace Blackwell GPU.

<Note>
Native DeepStream SDK installation on DGX Spark is **not** supported. Use the Docker
container method described below.
</Note>

<Note>
A compatible NVIDIA driver must be installed on the host for DGX Spark. The driver is not included in the Docker image; the NVIDIA Container Toolkit makes the host driver available to the container.
</Note>

Refer [NVIDIA DGX Spark Release Notes](https://docs.nvidia.com/dgx/dgx-spark/release-notes.html#current-software-versions) for stack details.

### Run DGX Spark Docker

1. Select the reviewed DeepStream SBSA-class image built for the upgrade stack.
   Set `DS_SBSA_IMAGE` to its tag or digest, then pull it if needed.

```bash
: "${DS_SBSA_IMAGE:?Set a reviewed DeepStream 9.2.1 DGX Spark Triton image reference}"
docker pull "$DS_SBSA_IMAGE"
```

2. Start the docker

```bash
sudo docker run -it --rm --runtime=nvidia --network=host \
    -e NVIDIA_DRIVER_CAPABILITIES=compute,utility,video,graphics \
    --gpus all \
    -e DISPLAY=:0 \
    -v /tmp/.X11-unix:/tmp/.X11-unix \
    -v /etc/X11:/etc/X11 \
    "$DS_SBSA_IMAGE"
```

<Note>
* `--privileged` is omitted above; add it only if the container needs access to all host devices or low-level driver operations. It grants near-root host access, so on shared or production systems prefer `--device` / `--cap-add` instead.
* The triton docker for DGX Spark is based on the SBSA Tritonserver image and has Ubuntu 24.04.
* When the triton docker is launched for the first time, it might take a few minutes to start since it has to generate compute cache.
* DGX Spark docker currently supports only nv3dsink for video display. nveglglessink is not supported.
* VIC is not supported on DGX Spark. Set tiler `compute-hw=1` (GPU) in your application config.
</Note>
