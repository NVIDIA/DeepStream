NVIDIA <sup>®</sup> DeepStream Software Development Kit (SDK) is an accelerated AI framework to build intelligent video analytics (IVA) pipelines. DeepStream runs on NVIDIA <sup>®</sup> T4, NVIDIA® Hopper, NVIDIA <sup>®</sup> Blackwell, NVIDIA <sup>®</sup> Ampere, NVIDIA <sup>®</sup> ADA, NVIDIA® DGX Spark, and platforms such as NVIDIA <sup>®</sup> Jetson AGX Thor, NVIDIA <sup>®</sup> Jetson Orin and NVIDIA <sup>®</sup> IGX Thor. For dGPU platforms Enterprise GPUs are highly recommended for deployments that are expected to run 24x7. Gaming GPUs are not designed to perform in such type of environments.

## Jetson Setup

This section explains how to prepare a Jetson device before installing the DeepStream SDK.

<Note>
Steps to install DeepStream SDK locally, assume that `~/.local/bin/` has been added to the `~/.bashrc` or `~/.profile`
</Note>

### Install Jetson SDK components

Download NVIDIA SDK Manager from https://developer.nvidia.com/embedded/jetpack. You will use this to install JetPack 7.2.1 GA (corresponding to L4T 39.2 release)

- NVIDIA SDK Manager is a graphical application which flashes and installs the JetPack packages.
- The flashing procedure takes approximately 10-30 minutes, depending on the host system.

### Install Dependencies

#### Install prerequisite packages

Enter the following commands to install the prerequisite packages:

```
$ sudo apt install \
libssl3 \
libssl-dev \
libcurl4-openssl-dev \
libgstreamer1.0-0 \
gstreamer1.0-tools \
gstreamer1.0-plugins-good \
gstreamer1.0-plugins-bad \
gstreamer1.0-plugins-ugly \
gstreamer1.0-libav \
libgstreamer-plugins-base1.0-dev \
libgstrtspserver-1.0-0 \
libjansson4 \
libyaml-cpp-dev \
libmosquitto1
```

<Note>
Sometimes with RTSP streams the application gets stuck on reaching EOS. This is because of an issue in rtpjitterbuffer component.
To fix this issue,
On baremetal, run a script "update_rtpmanager.sh" at `/opt/nvidia/deepstream/deepstream/`. The script should be executed once user installs packages mentioned under "Install Dependencies" section of Quickstart Guide.
On docker, users need to run user_additional_install.sh script to use the prebuilt binaries.
</Note>

##### Install OpenTelemetry

Enter the following commands to install OpenTelemetry:

```
$ cd ~
$ mkdir otel_src && cd otel_src && git clone --branch v1.23.0 --recurse-submodules https://github.com/open-telemetry/opentelemetry-cpp
$ cd opentelemetry-cpp
$ mkdir build && cd build
$ sudo apt install cmake
$ cmake .. -DBUILD_SHARED_LIBS=ON -DWITH_OTLP_GRPC=ON -DWITH_OTLP_HTTP=ON -DBUILD_TESTING=OFF
$ cmake --build . --parallel $(nproc)
$ ctest -V (Optional: run tests for verification)
$ sudo cmake --install .
```

<Note>
For more information, refer to the OpenTelemetry C++ installation guide:
https://github.com/open-telemetry/opentelemetry-cpp/blob/v1.23.0/INSTALL.md
</Note>

#### Install librdkafka (to enable Kafka protocol adaptor for message broker)

1. Install confluent-platform:

```
sudo mkdir -p /etc/apt/keyrings

wget -qO - https://packages.confluent.io/deb/8.0/archive.key | gpg \
--dearmor | sudo tee /etc/apt/keyrings/confluent.gpg > /dev/null

CP_DIST=$(lsb_release -cs)
echo "Types: deb
URIs: https://packages.confluent.io/deb/8.0
Suites: stable
Components: main
Architectures: $(dpkg --print-architecture)
Signed-by: /etc/apt/keyrings/confluent.gpg

Types: deb
URIs: https://packages.confluent.io/clients/deb/
Suites: ${CP_DIST}
Components: main
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/confluent.gpg" | sudo tee /etc/apt/sources.list.d/confluent-platform.sources > /dev/null

sudo apt-get update && sudo apt-get install confluent-platform
```

2. Install librdkafka:

```
sudo apt-get install librdkafka-dev
```

#### Install latest NVIDIA BSP packages

Installation of JetPack 7.2.1 GA will ensure that latest NVIDIA BSP packages are installed.

### Install the DeepStream SDK

<Note>
**Recommended for new users:** use **Method 4 (Docker container)** for the
quickest, dependency-free setup. For native installs, the Debian (Method 3)
and tar (Method 2) packages are published as GitHub release assets at
https://github.com/NVIDIA/DeepStream/releases/tag/v9.2.0.
</Note>

- **Method 1**: Using SDK Manager

  Select `DeepStreamSDK` from the `Additional SDKs` section along with JP 7.2.1 GA software components for installation.

- **Method 2**: Using the DeepStream tar package: https://github.com/NVIDIA/DeepStream/releases/tag/v9.2.0

   1.	Download the DeepStream 9.2 Jetson tar package `deepstream_sdk_v9.2.0_jetson.tbz2` to the Jetson device.

   2.	Enter the following commands to extract and install the DeepStream SDK:

```
$  sudo tar -xvf deepstream_sdk_v9.2.0_jetson.tbz2 -C /
$ cd /opt/nvidia/deepstream/deepstream-9.2
$ sudo ./install.sh
$ sudo ldconfig
```

- **Method 3**: Using the DeepStream Debian package: https://github.com/NVIDIA/DeepStream/releases/tag/v9.2.0

  Download the DeepStream 9.2 Jetson Debian package `deepstream-9.2_9.2.0-1_arm64.deb`  to the Jetson device. Enter the following command:

```
$ sudo apt-get install ./deepstream-9.2_9.2.0-1_arm64.deb
```

- **Method 4**: Use Docker containers

  DeepStream docker containers are available on NGC. See the [\DS_docker_containers](\DS_docker_containers) section to learn about developing and deploying DeepStream using docker containers.

<Note>
For scripted or headless downloads of the release assets using `curl` or `wget`, see [DS_Monorepo_FAQ](DS_Monorepo_FAQ).
</Note>

<Note>
Verification: Once DeepStream SDK installation is successful, refer to [Expected output (deepstream-app)](/text/DS_Quickstart#expected-output-deepstream-app) for the expected output.
</Note>

## dGPU Setup for Ubuntu

This section explains how to prepare an `Ubuntu x86_64` system with NVIDIA dGPU devices before installing the DeepStream SDK.

<Note>
Steps to install DeepStream SDK locally, assume that `~/.local/bin/` has been added to the `~/.bashrc` or `~/.profile`
</Note>

<Note>
This document uses the term dGPU (“discrete GPU”) to refer to NVIDIA GPU expansion card products such as NVIDIA |Tesla®| T4, NVIDIA® Hopper, NVIDIA <sup>®</sup> Blackwell, NVIDIA <sup>®</sup> Ampere, NVIDIA <sup>®</sup> ADA, NVIDIA |GeForce®| RTX 2080, NVIDIA |GeForce®| RTX 3080, NVIDIA |GeForce®| RTX 4080, NVIDIA |GeForce®| RTX pro 4500 and |GeForce®|/NVIDIA RTX/QUADRO.
This version of DeepStream SDK runs on GPUs supported by NVIDIA driver 595.58.03 and NVIDIA TensorRT™ 10.16.0.72 and later versions.

.. |Tesla®| replace:: Tesla\ <sup>®</sup>
.. |GeForce®| replace:: GeForce\ <sup>®</sup>
</Note>

### Prerequisites

You must install the following components:

- Ubuntu 24.04
- GStreamer 1.24.2
- NVIDIA driver 595.58.03
- CUDA 13.2
- TensorRT 10.16.0.72

#### Remove all previous DeepStream installations

Enter the following commands to remove all previous DeepStream 3.0 or prior installations:

```
$ sudo rm -rf /usr/local/deepstream /usr/lib/x86_64-linux-gnu/gstreamer-1.0/libgstnv* /usr/bin/deepstream* /usr/lib/x86_64-linux-gnu/gstreamer-1.0/libnvdsgst*
/usr/lib/x86_64-linux-gnu/gstreamer-1.0/deepstream*
/opt/nvidia/deepstream/deepstream*
$ sudo rm -rf /usr/lib/x86_64-linux-gnu/libv41/plugins/libcuvidv4l2_plugin.so
```

To remove DeepStream 4.0 or later installations:

1. Open the `uninstall.sh` file in `/opt/nvidia/deepstream/deepstream/`
2. Run the following script as `sudo ./uninstall.sh`

## dGPU on ARM Setup for Ubuntu

This section explains how to prepare an `Ubuntu aarch64` system with NVIDIA dGPU devices before installing the DeepStream SDK.

You must install the following components:

- NVIDIA driver 595.58.03
- Docker
- Nvidia Container Toolkit

### Install NVIDIA driver 595.58.03

- Download and install using NVIDIA driver 595.58.03 from NVIDIA Unix drivers page at: https://www.nvidia.com/en-us/drivers/details/266021/

- Run the following commands:

```
$ chmod 755 NVIDIA-Linux-aarch64-595.58.03.run
$ sudo ./NVIDIA-Linux-aarch64-595.58.03.run --no-cc-version-check
```

<Note>
Ensure gdm, lightdm or Xorg service is stopped while installing Nvidia driver

Use command : `sudo service gdm stop` `sudo service lightdm stop` `sudo pkill -9 Xorg`
</Note>

### Run dGPU on ARM Docker (SBSA)

<Note>
NVIDIA driver 580.159.03 is required for SBSA. The driver is bundled with the Docker image and does not need to be installed separately.
</Note>

1. Pull the DeepStream Triton Inference Server docker

```
docker pull nvcr.io/nvidia/deepstream:9.2-triton-sbsa-dgx-spark
```

2. Start the docker

```
sudo docker run -it --rm --runtime=nvidia --network=host -e NVIDIA_DRIVER_CAPABILITIES=compute,utility,video,graphics --gpus all -e DISPLAY=:0 -v /tmp/.X11-unix:/tmp/.X11-unix -v /etc/X11:/etc/X11 nvcr.io/nvidia/deepstream:9.2-triton-sbsa-dgx-spark
```

<Note>
`--privileged` is omitted above; add it only if the container needs access to all host devices or low-level driver operations. It grants near-root host access, so on shared or production systems prefer `--device` / `--cap-add` instead.
</Note>

## DGX Spark Setup for Ubuntu

This section explains how to prepare a [NVIDIA DGX Spark](https://www.nvidia.com/en-us/products/workstations/dgx-spark/)
system before installing DeepStream SDK. DGX Spark is an aarch64-based desktop AI system
running Ubuntu with an integrated NVIDIA Grace Blackwell GPU.

<Note>
Native DeepStream SDK installation on DGX Spark is **not** supported. Use the Docker
container method described below.
</Note>

<Note>
NVIDIA driver 580.159.03 is required for DGX Spark. The driver is bundled with the Docker image and does not need to be installed separately.
</Note>

Refer [NVIDIA DGX Spark Release Notes](https://docs.nvidia.com/dgx/dgx-spark/release-notes.html#current-software-versions) for stack details.

### Run DGX Spark Docker

1. Pull the DeepStream Triton Inference Server docker

```
docker pull nvcr.io/nvidia/deepstream:9.2-triton-sbsa-dgx-spark
```

2. Start the docker

```
sudo docker run -it --rm --runtime=nvidia --network=host \
    -e NVIDIA_DRIVER_CAPABILITIES=compute,utility,video,graphics \
    --gpus all \
    -e DISPLAY=:0 \
    -v /tmp/.X11-unix:/tmp/.X11-unix \
    -v /etc/X11:/etc/X11 \
    nvcr.io/nvidia/deepstream:9.2-triton-sbsa-dgx-spark
```

<Note>
* `--privileged` is omitted above; add it only if the container needs access to all host devices or low-level driver operations. It grants near-root host access, so on shared or production systems prefer `--device` / `--cap-add` instead.
* The triton docker for DGX Spark is based on the SBSA Tritonserver image and has Ubuntu 24.04.
* When the triton docker is launched for the first time, it might take a few minutes to start since it has to generate compute cache.
* DGX Spark docker currently supports only nv3dsink for video display. nveglglessink is not supported.
* VIC is not supported on DGX Spark. Set tiler `compute-hw=1` (GPU) in your application config.
</Note>
