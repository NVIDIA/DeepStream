> **Building from the GitHub mono-repo?** If you installed DeepStream by running `bash build/build.sh` from the
> [NVIDIA/DeepStream](https://github.com/NVIDIA/DeepStream) mono-repo, DeepStream is installed under
> `/opt/nvidia/deepstream/deepstream-9.2/` and you can follow the steps below as written. For the build steps,
> see [Install from the GitHub Mono-repo](/text/DS_Installation#install-from-the-github-mono-repo-build-from-source).

<Note>
This checkout targets DeepStream **9.2.1**. The x86 and generic SBSA Docker recipes
use Triton **26.10**, CUDA **13.4.3**, TensorRT **11.4.0.106** and cuDNN
**9.27.0.42**. Jetson has a separate JetPack **7.2.2+** target with CUDA
**13.2.2**, TensorRT **11.4.1.31** and cuDNN **9.20.0.46** on eligible AGX Orin
and Thor devices. See [Installation](/text/DS_Installation#deepstream-921-upgrade-targets)
for the complete target matrix. These are configured upgrade targets, not a
claim of completed platform qualification or newly published container tags.

For TensorRT 11 FP16 samples, follow the installed `samples/modelopt/README.md`
to prepare the models before running inference. Rebuild engines for the selected
stack; an older TensorRT engine is not a substitute for model preparation.
</Note>

## Jetson [Not applicable for NVAIE customers]

This section explains how to use DeepStream SDK on a Jetson device.

### Boost the clocks

After you have installed DeepStream SDK, run these commands on the Jetson device to boost the clocks:

```
$ sudo nvpmodel -m 0
$ sudo jetson_clocks
```

<Note>
Select a power mode supported by your device and JetPack release; mode numbers
are device-specific. The TensorRT 11 target above applies to AGX Orin and Thor,
not every Orin module supported by earlier SDK stacks.
</Note>

You should run these commands before running DeepStream application.

### Run deepstream-app (the reference application)

1. Navigate to the configs/deepstream-app directory on the development kit.

   $ cd /opt/nvidia/deepstream/deepstream-9.2/samples/configs/deepstream-app

2. Enter the following command to run the reference application:

```
     # deepstream-app -c <path_to_config_file>

     e.g. $deepstream-app -c source30_1080p_dec_infer-resnet_tiled_display.txt
```

Where `<path_to_config_file>` is the pathname of one of the reference application’s configuration files, found in `configs/deepstream-app/`. See Package Contents in `configs/deepstream-app/` for a list of the available files.

Config files that can be run with deepstream-app:

a. `source30_1080p_dec_infer-resnet_tiled_display.txt`

b. `source30_1080p_dec_preprocess_infer-resnet_tiled_display.txt`

c. `source4_1080p_dec_infer-resnet_tracker_sgie_tiled_display.txt`

d. `source1_usb_dec_infer_resnet.txt`

e. `source1_csi_dec_infer_resnet.txt`

f. `source2_csi_usb_dec_infer_resnet.txt`

g. `source6_csi_dec_infer_resnet.txt`

h. `source2_1080p_dec_infer-resnet_demux.txt`

i. `source4_1080p_dec_infer-resnet_tracker_sgie_tiled_display.yml`

j. `source30_1080p_dec_infer-resnet_tiled_display.yml`

k. `source4_1080p_dec_preprocess_infer-resnet_preprocess_sgie_tiled_display.txt`

l. `source2_dewarper_test.txt`

<Note>
* Refer to [Sample Configurations and Streams](/text/DS_sample_configs_streams) for detailed explanation of each configuration file.
</Note>

<Note>
* You can find sample configuration files under `/opt/nvidia/deepstream/deepstream-9.2/samples` directory. Enter this command to see application usage:

```
$ deepstream-app --help
```

* To save TensorRT Engine/Plan file, run the following command:

```
$ sudo deepstream-app -c <path_to_config_file>
```

</Note>

  1. To show labels in 2D Tiled display view, expand the source of interest with mouse `left-click` on the source. To return to the tiled display, `right-click` anywhere in the window.
  2. Keyboard selection of source is also supported. On the console where application is running, press the `z` key followed by the desired row index (0 to 9), then the column index (0 to 9) to expand the source. To restore 2D Tiled display view, press `z` again.

### Run precompiled sample applications

1. Navigate to the chosen application directory inside `sources/apps/sample_apps`.
2. Follow the directory’s README file to run the application.

<Note>
If the application encounters errors and cannot create Gst elements, remove the GStreamer cache, then try again. To remove the GStreamer cache, enter this command:
`$ rm ${HOME}/.cache/gstreamer-1.0/registry.aarch64.bin`

When the application is run for a model which does not have an existing engine file, it may take up to a few minutes (depending on the platform and the model) for the file generation and the application launch. For later runs, these generated engine files can be reused for faster loading.
</Note>

## How to visualize the output if the display is not attached to the system

### 1 . Running with an X server by creating virtual display

Refer https://docs.nvidia.com/grid/latest/grid-vgpu-user-guide/index.html#configuring-xorg-server-on-linux-server for details.

### 2 . Running without an X server (applicable for applications supporting RTSP streaming output)

The default configuration files provided with the SDK have the EGL based `nveglglessink` as the default renderer (indicated by type=2 in the [sink] groups). The renderer requires a running X server and fails without one.
In case of absence of an X server, DeepStream reference applications provide an alternate functionality of streaming the output over RTSP. This can be enabled by adding an RTSP out sink group in the configuration file. Refer to `[sink2]` group in `source30_1080p_dec_infer-resnet_tiled_display.txt` file for an example. Don’t forget to disable the `nveglglessink` renderer by setting enable=0 for the corresponding sink group.

## DeepStream Triton Inference Server Usage Guidelines

<Note>
* Before running `prepare_classification_test_video.sh`, refer note in section [Docker Containers](/text/DS_docker_containers).
</Note>

### dGPU

1. Select a reviewed DeepStream image built from this checkout's
   `deepstream_dockers/x86_dockerfiles/Dockerfile_triton_x86`, then pull it if it
   is stored in a registry. Set `DS_X86_IMAGE` to its tag or digest.

```bash
: "${DS_X86_IMAGE:?Set a reviewed DeepStream 9.2.1 x86 Triton image reference}"
docker pull "$DS_X86_IMAGE"
```

2. Start the docker

```bash
docker run --gpus "device=0" -it --rm -v /tmp/.X11-unix:/tmp/.X11-unix -e DISPLAY="$DISPLAY" -e CUDA_CACHE_DISABLE=0 "$DS_X86_IMAGE"
```

<Note>
* The x86 recipe uses matching AMD64 `26.10-py3` server and `26.10-py3-sdk`
  client stages (Triton 2.74.0, Ubuntu 24.04 / Python 3.12). The raw Triton base
  image does not itself contain DeepStream. Existing published `9.2-*` tags
  must not be assumed to contain this upgraded stack.

* When the triton docker is launched for the first time, it might take a few minutes to start since it has to generate compute cache.
</Note>

### ARM SBSA (GH200, GB200, DGX Spark)

1. Select a reviewed DeepStream image built from this checkout's
   `deepstream_dockers/sbsa_dockerfiles/Dockerfile_SBSA_Triton`. Set
   `DS_SBSA_IMAGE` to its tag or digest, then pull it if needed.

```bash
: "${DS_SBSA_IMAGE:?Set a reviewed DeepStream 9.2.1 SBSA Triton image reference}"
docker pull "$DS_SBSA_IMAGE"
```

2. Start the docker

```bash
sudo docker run -it --rm --runtime=nvidia --network=host -e NVIDIA_DRIVER_CAPABILITIES=compute,utility,video,graphics --gpus all -e DISPLAY=:0 -v /tmp/.X11-unix:/tmp/.X11-unix -v /etc/X11:/etc/X11 "$DS_SBSA_IMAGE"
```

<Note>
* `--privileged` is omitted above; add it only if the container needs access to all host devices or low-level driver operations. It grants near-root host access, so on shared or production systems prefer `--device` / `--cap-add` instead.

* The SBSA recipe uses matching ARM64 `26.10-py3` server and `26.10-py3-sdk`
  client stages (Triton 2.74.0, Ubuntu 24.04 / Python 3.12), plus genuine SBSA
  VPI 4.1.6 inputs. It is not a Jetson image.

* When the triton docker is launched for the first time, it might take a few minutes to start since it has to generate compute cache.

* ARM SBSA docker currently supports only nv3dsink for video display.
</Note>

### Jetson

Build the Jetson Triton image using this checkout's
`deepstream_dockers/jetson_dockerfiles/Dockerfile_Jetson_Devel`. Supply reviewed,
matching `JETSON_TRITON_IMAGE` and `JETSON_TRITON_SDK_IMAGE` providers for the
JetPack 7.2.2+ / TensorRT 11.4.1.31 stack. The runtime-only recipe instead takes
`JETSON_RUNTIME_IMAGE`; it does not add Triton to a base that lacks it. See
[Docker Containers](/text/DS_docker_containers#deepstream-921-upgrade-recipes).

Stock SBSA Triton 26.10 and the old JetPack 26.04 archives are not substitutes
for a matching Jetson provider. No new public Jetson image tag is assumed here.
The resulting Triton image must already contain compatible server and backend
libraries; no backend installer is needed for that Docker path.

For an optional native archive installation, the **monorepo**
`scripts/triton_backend_setup.sh` requires explicit matching `TRITON_PKG_PATH`
and `TRITON_CLIENT_SDK_PKG_PATH` URLs. It has no 26.04 fallback, and installing
archives does not qualify their compatibility. Its backend directory is
`/opt/tritonserver/backends`. Follow the selected provider's layout when setting
`model_repo.backend_dir` in an inference configuration.

### Single process

<Note>
DLA usecases are not applicable on Jetson Thor
</Note>

DeepStream reference application supports multiple configs in the same process. To run DLA and GPU in same process, set environment variable `CUDA_DEVICE_MAX_CONNECTIONS` as `32`:

```
$ deepstream-app -c <gpuconfig> -c <dla0config> -c <dla1config>
```
